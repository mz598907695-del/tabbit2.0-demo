## 性能改动与证据

| 项目 | 整理前 | 整理后 | 保持的行为 |
| --- | --- | --- | --- |
| 本地壁纸读取 | `getAll()` 先把官方备份和个人图片全部读入，再过滤 | 先读键，只取个人图片 Blob | 原始备份保留，排序/校验/删除/上传路径不变 |
| 拖拽预览 | 每个 pointermove 都更新 React 卡片树 | 每个事件仍计算几何，仅预览状态每帧合并 | 阈值、吸附、边缘滚动逐事件计算；松手立即提交，取消/卸载清空排队预览 |
| 文件提示监听 | 每个文件常驻 scroll/blur/resize 监听 | 仅悬停等待或提示显示期间监听 | 400ms 延迟、移开/滚动取消、定位和文案不变 |
| 图片亮度分析 | 每个像素的每个颜色通道计算幂函数 | 预计算 256 个线性通道值并查表 | 仍为 64×64、线性亮度与 alpha 加权，阈值为 0.4 |
| 侧栏滚动条 | 观察过的已移除节点留到整个组件销毁 | 内容变化时 unobserve 已移除节点 | 滚动条尺寸、位移、拖拽逻辑不变 |
| 其他开销 | 无关更新会重建部分回调、搜索列表或重复写样式 | 稳定 history 命令/空间 context，搜索关闭时不建结果，几何不变不重写侧栏宽度 | 配置、搜索结果与几何值不变 |
| 日期卡片 | 每分钟生成新状态并重绘 | 保留轮询，只在日期变化时更新状态 | 日期切换精度不变，隐藏/预览卡片仍不运行日期计时器 |

原生桌面 WebKit 对比：

- 40 张卡片、60 次相同拖拽采样：React 更新由 **59 次降至 27 次**，最终保存对象完全一致；取消后没有残留拖拽 DOM。
- 8 个输出物的全局提示监听：空闲 **24 → 0**，悬停等待 **24 → 3**，滚动取消 **24 → 0**。
- 独立真实 IndexedDB：43 张官方备份 + 1 张个人图片，仅执行 1 次 `getAllKeys` 和 1 次个人图片 `get`；未修改用户数据库。
- 200 次 64×64 图片分类：本机样本 **31ms → 2ms**；阈值边界、透明像素、256 个灰度和 1000 组确定性 RGBA 数据与旧实现一致。
- 侧栏 8 → 4 个内容节点：观察对象 **9 → 5**，旧实现仍为 9；四个滚动位置的尺寸与位移完全一致。

这些是本机开发环境中的定向测量，不是所有设备、所有页面的统一性能承诺。
